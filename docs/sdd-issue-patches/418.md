## Contrato de tests (obligatorio en el PR)

Archivo sugerido: `tests/unit/test_public_queue_sync.py` (sin red real; mock de `gh` / HTTP; sin inventar cuenta GitHub).

1. **Rechazo:** una línea que `share_refusal` marca (correo no-ejemplo, teléfono, ruta `/Users/…`) **no** entra en la cola; nada de PR.
2. **Sin red:** con el transporte fallando, la cola **se conserva** en disco y el comando de búsqueda / observación **sigue** (no aborta el loop local por el sync).
3. **PR idempotente:** reintentar el mismo lote **no** abre un segundo PR (mismo head/batch id o equivalente comprobable).
4. **`-U`:** tras un merge en `main` (fixture de snapshot), `jobbot -U` (o el paso de catálogo que el PR documente junto a la reinstalación) actualiza la copia local; una entrada **ajena** queda `candidate`, no `active`.
5. **PII:** el payload encolado / del PR no contiene correo, teléfono ni home path (asserción sobre el YAML/JSON del lote).

## Justificación

`companies export` ya arma el snapshot; `#106` rechaza PII. Sin cola durable + PR de lote, cada máquina silencia el aporte o inventa un push con secretos. Separar encolar → PR → `-U` mantiene el mapa en git (HITL remoto) y el viajero local (`JobBot`) solo importa candidatos, nunca promueve solo.
