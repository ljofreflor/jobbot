## SDD / patrones

- **SDD:** `docs/software-design.md` §3.1 `ProfileAdapter` · §3.5 plan-then-apply (pull = lectura; sync aparte) · LinkedIn read-only default
- **Patrón(es):** Adapter pull por sección (`/in/<slug>/details/<sección>/`); Result por sección (`ok` con filas | `empty` intencional | `unread` fallo de lectura) — **empty ≠ unread**; Parser offline sobre `main` por bloques (sin depender de `h1` / `id=about`)
- **UML:** [`docs/uml.md#linkedin-details-pull`](../uml.md#linkedin-details-pull) · [`ports`](../uml.md#ports)
- **Cambio de diagrama:** el PR tipa el outcome por sección y actualiza `linkedin-details-pull`

## Contrato de tests (obligatorio en el PR)

Archivo sugerido: `tests/unit/test_linkedin_details_pull.py` (fixtures HTML; sin Playwright real / sin red).

1. **Experiencia con dos bloques:** fixture `/details/experience/` → guarda cargo y empresa de cada bloque (sin inventar fechas ni logros ausentes del HTML).
2. **Vacío intencional:** texto tipo `No hay nada que ver por ahora` → sección **vacía** (`empty`), no `unread` / no ops failure de lectura.
3. **Sección ausente:** si el fixture de experiencia no está (o no se pudo leer), esa sección queda **`unread`**; las demás secciones leídas se conservan en el snapshot.
4. **Titular:** sale del bloque superior del perfil / details; no exige `data-testid=headline` ni `h1` en el DOM antiguo.
5. **Solo lectura:** ningún test ni código pulsa controles de edición en LinkedIn.

## Justificación

El perfil público dejó de exponer las secciones en el overview. Seguir parseando selectores muertos produce snapshots vacíos o inventados. Leer `/details/<sección>/` con outcomes distintos (vacío real vs no leído) mantiene el pull auditable y alineado con #194 (snapshot vacío) sin tocar sync con escritura (#284).
