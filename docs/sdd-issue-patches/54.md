## SDD / patrones

- **SDD:** `docs/software-design.md` §3.5 plan-then-apply · Design economics (una mejora acotada → System 1) · never invent · HITL
- **Patrón(es):** **Command** `cv tune-for` (ingest URL opcional → advise acotado a un `JobPosting`); **budget** (3–5 sugerencias); reusa detector de invención / no-drop de cifras; `--apply` confirma una por una con backup
- **UML:** [`docs/uml.md#cv-tune-for`](../uml.md#cv-tune-for) · [`plan-apply`](../uml.md#plan-apply) · [`fact-preference`](../uml.md#fact-preference)
- **Cambio de diagrama:** el PR tipa el flujo tune-for (scope + budget + HITL) y actualiza `cv-tune-for`

## Contrato de tests (obligatorio en el PR)

Archivo sugerido: `tests/unit/test_cv_tune_for.py` (fixtures de JD + perfil; sin red ni LLM obligatorio).

1. **URL:** `tune-for` con hard-link fixture llama ingest (`get`) y luego advise sobre el `Jxxxx` guardado.
2. **ID:** `tune-for Jxxxx` carga el aviso almacenado sin re-fetch.
3. **Budget:** como máximo N sugerencias (3–5) por corrida; el resto no se muestra.
4. **No invention / no drop:** sugerencia que inventa skill o borra cifra/nombre propio se descarta (mismo gate que `cv advise`).
5. **`--apply`:** confirma una por una; escribe `profile.yaml.bak.<stamp>` antes de mutar; `skip-all` corta.
6. **Fuera:** no reescribe el CV entero hacia un aviso; `cv build --job` sigue siendo la proyección derivada.

## Justificación

Un aviso debe enseñar wording de mercado al baseline (~5% de presentación), no clonar el CV. Tipar scope + budget + HITL evita que un agente “optimice” el SoT por cada vacante.
