## SDD / patrones

- **SDD:** `docs/software-design.md` §3.1 `JobSourceAdapter` · §3.2 Factory · §7 Extension checklist (falla ≠ lista vacía)
- **Patrón(es):** Result object / discriminated outcome (`ok` | `source_failed` | `off_topic` | `challenge`); Adapter no traga HTTP 400 como `[]`; CLI imprime el outcome, no solo `No jobs found`
- **UML:** [`docs/uml.md#search-outcome`](../uml.md#search-outcome) · [`ports`](../uml.md#ports) · [`hitl-pause`](../uml.md#hitl-pause)
- **Cambio de diagrama:** el PR tipa `SearchOutcome` (o equivalente) y actualiza `search-outcome`

## Contrato de tests (obligatorio en el PR)

Archivos sugeridos: `tests/unit/test_torre_search_outcome.py`, `tests/unit/test_getonboard_search_relevance.py` (fixtures offline; sin red).

1. **Torre HTTP 400:** un `Fetcher` (o fixture) que levanta/simula HTTP 400 hace que la búsqueda informe **fuente caída** (`source_failed` / mensaje claro) y **no** imprima `No jobs found` como único resultado; exit distinto del de cero avisos reales (p. ej. ops failure o código documentado).
2. **Get on Board off-topic:** un aviso cuyo título no contiene la frase consultada **no** se cuenta como hallazgo de esa frase (lista aparte `off_topic` o filtrado con reporte); no engorda el conteo de matches de la query.
3. **Desafío (Cloudflare / challenge page):** una sola pasada; no bucle de recarga; no se resuelve CAPTCHA; outcome `challenge` (alineado con #184 / #392).
4. **Cero avisos real:** respuesta 200 con lista vacía o sin filas relevantes → sí puede decir que no hay avisos, sin marcar `source_failed`.

## Justificación

Una lista vacía es ambigua: puede ser “no hay vacantes”, “la API cayó”, “el board devolvió otro oficio” o “un challenge bloqueó la lectura”. El contrato auditable exige **outcomes distintos** para que `ops failure` y el candidato no traten un 400 de Torre como mercado vacío.
