## SDD / patrones

- **SDD:** `docs/software-design.md` §3.8 / NL offload · `nlp/gateway.run_optional_llm` · never invent · `cv advise --llm` como precedente
- **Patrón(es):** Optional LLM detrás de `jobbot[llm]` + `OPENAI_API_KEY`; **Validator** post-LLM (cada campo citado debe aparecer en el texto del aviso); fallback al parser determinista si no hay key, falla la red o inventa; el perfil (`Candidate`) **no** se reescribe
- **UML:** [`docs/uml.md#jd-llm-extract`](../uml.md#jd-llm-extract) · [`ports`](../uml.md#ports) · [`plan-apply`](../uml.md#plan-apply)
- **Cambio de diagrama:** el PR tipa `JdExtract` / gate de anclaje al texto y actualiza `jd-llm-extract`

## Contrato de tests (obligatorio en el PR)

Archivo sugerido: `tests/unit/test_jobs_add_llm.py` (sin red; sin API key real; mock del gateway).

1. **Sin `OPENAI_API_KEY`:** `jobs add --file PATH --llm` no llama a la red; queda el parseo determinista.
2. **Invención:** un resultado LLM (mock) que nombra una empresa **ausente** del texto se **descarta**; no se upserta ese valor; se conserva el determinista (o se falla el campo inventado).
3. **Anclado:** un resultado que repite título y una skill que **sí** están en el texto se acepta y se guarda en el `JobPosting` (no en `profile.yaml`).
4. **Contacto:** el prompt al LLM usa texto con contacto redactado (`pii_guard.redact`), nunca el correo/teléfono crudo del aviso.
5. **Suite offline:** la suite corre sin `OPENAI_API_KEY` y sin el extra `llm`.

## Justificación

El parser determinista no cubre prosa libre; un LLM sin gate inventa empleadores y skills. El mismo contrato que `cv advise --llm` (validación determinista después del modelo) aplica al JD: hechos solo si el texto del aviso los sostiene; el perfil nunca se toca desde `jobs add`.
