## Contrato de tests (obligatorio en el PR)

Archivo sugerido: `tests/unit/test_indeed_challenge_tty.py` (o ampliar el módulo de `browser/manual` / Indeed jobs).

1. **No-TTY + desafío:** con `stdin_available=False` (o `sys.stdin.isatty` → False) y una página que `_looks_like_challenge` marca como desafío, `_clear_challenge` **no** invoca espera de 300 s (`pause_for_manual` / `wait_for_manual_clear` no hacen poll largo); el flujo de búsqueda/get sale con código **4** y registra ops failure con clase de desafío (sin mensaje de “0 avisos”).
2. **TTY + desafío:** con stdin TTY, la espera de hasta 300 s (o `input()` / poll con `is_clear`) sigue disponible; un `is_clear` que se pone en True antes del timeout deja seguir el flujo.
3. **Sin desafío:** `_clear_challenge` retorna True sin pausa, con o sin TTY.
4. **Fixture offline:** HTML/fixture de desafío; sin Playwright real; sin red.

## Justificación

Sin TTY (agente, CI, pipe) la pausa de 5 minutos es tiempo muerto: nadie puede resolver el CAPTCHA en esa sesión. Fallar rápido (exit 4) es el contrato auditable; el bypass del desafío queda prohibido.
