## SDD / patrones

- **SDD:** `docs/software-design.md` §3.1 `JobSourceAdapter` · polite web / robots · decisión de términos (#227) como **Guard** antes de I/O
- **Patrón(es):** **Guard** `terms_allowed` (hoy `false` → exit 2, sin red); **JobSourceAdapter** `LaborumDiscover` que, solo si la marca es permitida, parsea sitemap (fixture) → `JobPosting` (título + URL); filtro robots: URLs de listado/filtros prohibidas no se upsertan
- **UML:** [`docs/uml.md#laborum-sitemap-terms`](../uml.md#laborum-sitemap-terms) · [`ports`](../uml.md#ports) · [`search-outcome`](../uml.md#search-outcome)
- **Cambio de diagrama:** el PR tipa la marca de términos + lector de sitemap y actualiza `laborum-sitemap-terms`

## Contrato de tests (obligatorio en el PR)

Archivo sugerido: ampliar `tests/unit/test_laborum_discover.py` (sin red).

1. **Marca no:** con términos no permitidos (estado actual / flag off), `jobs discover --source laborum --fixture …` (o sin fixture) sale **2**, no lee el fixture, 0 avisos guardados (comportamiento #227).
2. **Marca sí + sitemap:** con la marca permitida y un sitemap de prueba con **dos** URLs de aviso, se guardan **dos** avisos con títulos conocidos del fixture.
3. **Robots:** una URL de página de filtros que `robots.txt` (fixture) prohíbe **no** se guarda aunque aparezca en el sitemap.
4. **Offline:** el test no abre sockets a laborum.cl.

## Justificación

#227 bloquea la descarga hasta decidir términos; sin un lector detrás de esa marca, el “sí” futuro no tiene camino testeable. Separar Guard (política) de Adapter (sitemap) evita mezclar un permiso legal con el parseo, y el fixture permite CI sin tocar el host vivo.
