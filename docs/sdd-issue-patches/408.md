## SDD / patrones

- **SDD:** `docs/software-design.md` §2 presentation (`cv build`) · §8 Overlay/Projection (sin segundo SoT) · never invent
- **Patrón(es):** **Projection** de frases derivadas (`output/cv/{lang}.yaml` por `id`); **Validator** de #34 (`cv translate`) como gate; `cv build --lang` **lee** lo aceptado y cae al texto base si falta; **nunca** escribe `profile.yaml` (distinto del overlay `profile.en.yaml` / #400)
- **UML:** [`docs/uml.md#cv-derived-translation`](../uml.md#cv-derived-translation) · [`fact-preference`](../uml.md#fact-preference) · [`ports`](../uml.md#ports)
- **Cambio de diagrama:** el PR tipa `DerivedCvTexts` / selección por id y actualiza `cv-derived-translation`

## Contrato de tests (obligatorio en el PR)

Archivo sugerido: `tests/unit/test_cv_build_lang.py` (fixture de perfil + `output/cv/en.yaml`; sin red; sin PDF real si se puede asertar el texto intermedio).

1. **Frase aceptada:** con un logro cuyo id tiene frase en `output/cv/en.yaml` que `cv translate` aceptaría, el CV en inglés (`cv build --lang en`) contiene **esa** frase y **no** el texto base de ese id.
2. **Sin archivo:** sin `output/cv/en.yaml` (o sin esa entrada), el CV usa el texto base e imprime `no translation; the source text stays` (o el mensaje fijado en el PR); se informa por id.
3. **Perfil intacto:** en ambos casos el hash/contenido de `profile.yaml` no cambia.
4. **Gate #34:** una frase que fallaría `cv translate` (cifra distinta, pierde empresa del texto, skill inventada) **no** se usa en el build — se cae al base (o se rechaza con el mismo criterio); no se inventa al armar el TeX/PDF.

## Justificación

Validar la traducción (#34) sin consumirla deja el inglés muerto en disco. Consumirla sin el gate reintroduce invención en el artefacto. Separar `output/cv/en.yaml` (derivado por build) de `profile.en.yaml` (#400, overlay de hechos) evita un segundo SoT: el perfil sigue siendo la verdad; el build solo presenta.
