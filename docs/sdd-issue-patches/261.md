## SDD / patrones

- **SDD:** `docs/software-design.md` §8 fila dual brand · manifiesto §7 (si nombra dualidad) · hermanos #164 #130 #162 (nombre del mapa)
- **Patrón(es):** **Value Object** `Brand` (`engine_name` estable + `product_name` configurable); **Facade** de presentación (firma / crédito CV / copy público); **Decision Record** HITL para el nombre público definitivo; **Anti-corruption** (no rename del import/binario bajo el nombre de cara)
- **UML:** [`docs/uml.md#dual-brand`](../uml.md#dual-brand) · se cita desde [`namesake-usecase-map`](../uml.md#namesake-usecase-map) · [`commons-vs-traveller`](../uml.md#commons-vs-traveller) (JobBotName en el viajero)
- **Cambio de diagrama:** el PR que cierre la elección tipa `Brand` y la fuente de config (`[brand]` / env); no renombra el paquete `jobbot`

## Contrato de tests (obligatorio al cerrar)

1. **`jobbot.branding`** (o módulo equivalente) expone motor vs cara pública sin hardcodear un nombre inventado en silencio.
2. **Config** `[brand]` / `JOBBOT_PRODUCT_NAME` documentada en ejemplo toml; default seguro si falta.
3. **HITL:** el `product_name` definitivo queda escrito en el issue (o Decision Record) antes de usarlo en home/#130.
4. **Fuera de alcance verificado:** ningún commit renombra el entrypoint `jobbot` ni el import path como parte de este issue.

## Justificación

Homónimos (#164) hacen caro pelear el nombre del motor. Dual brand separa PyPI/CLI de la cara pública sin un rename destructivo; la elección del nombre público es humana.
