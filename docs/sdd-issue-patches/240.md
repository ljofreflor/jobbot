## Contrato de tests (obligatorio en el PR)

Archivo sugerido: ampliar `tests/unit/test_empleospublicos_source.py` + fixtures de feed (sin red).

1. **Sin fixture obligatorio:** fetcher falso con `feed_nueva` + `feed_pizarron` → unión sin duplicados; `--dry-run` no escribe; mensaje fixture-first desaparece.
2. **Renta:** `"1,00"` / `0` / vacío → `salary_text=None` + nota «renta no informada» (nunca $1).
3. **Clave estable:** fila sin `?i=` → `source_job_id` con prefijo `k:` idempotente entre corridas.
4. **Cierre vencido:** `closes_at` ayer en `America/Santiago` → no se guarda como vigente.
5. **403 sin browser:** exit **4** (`MANUAL_CHALLENGE`); mensaje menciona `--browser` y `--feed-file`.
6. **CDP:** `--browser` + sesión falsa que `fetch()` same-origin → guarda; UA de JobBot no se disfraza de Chrome genérico.
7. **Aislamiento:** un feed falla y el otro responde → se guardan los del sano; exit 0.
8. **URL externa:** fila a `empleo.sii.cl` / `*.trabajando.cl` → `url` esa y `ats_kind` detectado, no forzar `empleos_publicos`.
9. **Offline:** abrir socket real hace fallar el test.

## Justificación

Los feeds públicos dan volumen real para perfiles no técnicos, pero el cliente plano recibe 403. Separar Strategy HTTP vs CDP (HITL de sesión humana) evita spoofing y deja claro el outcome: challenge ≠ mercado vacío. Unir dos feeds con dedupe es el contrato de discover; postular (ClaveÚnica) queda fuera.
