## Contrato de tests de este issue (el mapa)

Archivo sugerido: `tests/unit/test_capability_gap_map.py` (parsea este patch o `docs/uml.md#capability-gap-map`).

1. **Cobertura:** las seis filas del mapa aparecen en el documento canónico (patch o UML) con patrón + contrato.
2. **No-implementación:** cerrar #424 no exige módulos de producto nuevos; un PR que solo borre el mapa sin contratos falla el criterio del issue (“sin un contrato nuevo no cumple”).
3. **Negativos:** el mapa nombra explícitamente fuera de alcance: autopilot, OAuth bandeja, inventar experiencia, #422 followup.

## Justificación

Robar casos de uso (#155/#164) sin contrato produce issues eternos o clones de throughput. El mapa fuerza System 2 → System 1: cada hueco nombra patrón, test y (si hace falta) issue hijo antes de escribir código.
