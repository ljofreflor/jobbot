## SDD / patrones

- **SDD:** `docs/software-design.md` §3.1 `JobSourceAdapter` · Registry / Factory (§3.2) · coverage indicator (#265) · polite web / robots
- **Patrón(es):** **JobSourceAdapter** `AiraDiscover` (`jobs.airavirtual.com/{slug}`); **Registry** de slugs solo desde el catálogo/companies (nunca enumerar el host ni inventar slug desde el nombre de marca); **ACL** empleador = dueño del canal, no «Aira»; **SearchOutcome** (403/robots = refused, no «cero avisos»)
- **UML:** [`docs/uml.md#aira-slug-discover`](../uml.md#aira-slug-discover) · [`ports`](../uml.md#ports) · [`search-outcome`](../uml.md#search-outcome)
- **Cambio de diagrama:** el PR tipa discover por slug de catálogo y actualiza `aira-slug-discover`

## Contrato de tests (obligatorio en el PR)

Archivo sugerido: `tests/unit/test_aira_discover.py` + fixtures HTML (sin red).

1. **Slugs del registro:** sin `--site`, solo se recorren canales con `ats_family`/`ats: aira` ya observados; un slug inventado no se pide.
2. **Mapeo:** fixture de listado → `JobPosting` con título, URL canónica, empleador del canal (no «Aira»), `source=aira`, dedupe `plataforma+slug+id`; sin fecha en la página → `posted_at`/`closes_at` ausentes (no inventar).
3. **Robots / rechazo:** path prohibido o HTTP 403 → outcome refused / mensaje claro, **no** «No jobs found» como único resultado (#390).
4. **Coverage:** al validar `job_listing` en un canal, ese canal pasa de `pending` a `proven` en el indicador; identificar ≠ habilitar autopilot.
5. **Offline:** la suite no abre sockets a `jobs.airavirtual.com`.

## Justificación

Aira es el segundo desbloqueo del catálogo CL (#265): un host, muchos empleadores por slug. El slug no se deduce de la marca; sale del canal observado. Separar Adapter (parse) de Registry (qué slugs existen) evita un crawler que invente URLs y deja el envío humano fuera del discover.
