## Contrato de tests (obligatorio en el PR)

Archivo sugerido: `tests/unit/test_tutorial_entry_door.py` (lee markdown + help; sin red).

1. **Tutorial feliz:** el documento de tutorial de entrada (p. ej. `docs/blog/posts/2026-10-19-tutoriales-01-primeros-pasos.md` y/o el tramo del README/tutorial marcado como camino feliz) **antes** de la primera aparición de la palabra `advanced` (o encabezado equivalente «Avanzado» / «Advanced») **no** contiene las subcadenas de comando `indeed`, `linkedin` ni `getonboard` (como nombres de grupo CLI; casefold).
2. **Portal sigue vivo:** `jobbot indeed --help` (o `uv run jobbot indeed --help`) sale **0** y la salida menciona Indeed.
3. **Ayuda raíz (#108):** si el PR también toca el epígrafe de `jobbot --help`, la primera aparición de `profile`, `cv`, `get` y `capture` es anterior a la de `indeed` (criterio ya fijado en #108).
4. **Sin borrado:** los módulos Typer `indeed_app` / `linkedin_app` / `getonboard_app` siguen registrados (asserción de registro o help ≠ «No such command»).

## Justificación

Decenas de grupos al mismo nivel en el tutorial empujan al candidato a sync de portales antes de tener perfil y un aviso. La puerta corta (profile → cv → get/capture) es el mismo progressive disclosure que `#108` pide en `--help`; los portales no se borran — solo dejan de competir en el primer viewport del aprendizaje.
